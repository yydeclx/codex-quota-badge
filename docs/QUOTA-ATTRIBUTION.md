# 周额度的本机与非本机归因（v1.5.6）

官方周额度只提供账号总量，不是逐设备账单。本机、非本机均为估算，只显示这两项整数；总量始终等于 100 减去所选账号剩余额度。

## 原始证据

- 使用主副账号各自的额度缓存、账号缓存历史
- 补读本机原生响应的主账号额度时，创建者身份散列必须匹配当前主账号缓存身份，且周窗口、重置时间匹配；这是关联证据，不是逐请求扣费证明
- 本机请求从 usage.jsonl 有界增量读取，排除第三方渠道和未计用量失败请求，不再叠加原生 Token 日志
- 明确实际账号的请求只归该账号；无账号字段的请求使用主账号身份及周窗口匹配的原生额度响应，与同时间段本机请求相关联；不依赖副账号是否更新。明确属于其他账号的请求仍排除，不按当前选择猜扣费账号
- 旧估算账本完全不作为新校准证据；即使重置时间或账号角色匹配，也不据此认定身份相同。原始额度端点单独存储并校验身份

## 计算

1. 以同账号额度下降和关联请求工作量校准经验系数；有请求但额度暂未下降的区间也计入工作量
2. 工作量采用缓存折减后的输入与输出 Token 指标，系数来自实测，不是官方计费公式，不能跨账号、跨周期套用
3. 本机估算为工作量乘以经验系数，最多为该区间总下降；余量估为非本机
4. 初始缺口和长断档用同账号经验关系回推。缺少校准时，本机只计有依据部分，未获本机证据的余量暂估为非本机，并标低置信；这不能证明其他设备实际使用了全部余量
5. 本机日期跟随请求发生日期，非本机日期不足时按额度采样区间分摊；柱状图不是官方每日账单
6. 回升按净消耗校正，120秒以内重置时间抖动归并，新周期重新校准。原始观察与估算账本分开，旧估算比例不作为新证据
7. 万分之一百分点账本与整数显示闭合，日、来源、周期总量一致

## 保留与资源

旧错误归因在首次重算前保留 .attribution-v1-backup.json，未区分账号的旧历史原件不修改。新原始证据保存在 quota-attribution-state.json，普通升级不会覆盖。

复用已有额度刷新工作线程，有界读取、文件签名缓存和增量解析，无新增网络、线程、定时器或网关补丁。解析失败不影响账号余额显示，不退回五五分。

并发设备、账号池缺少逐请求身份、原生直连缺少网关记录、早期样本缺失都会降低可信度。界面保留估算与置信度，现有本机证据不能还原精确逐设备账单。

主账号近期响应额度下降与本机请求直接对应时，优先采用该时间关联，不再用全周期Token经验系数压低本机份额。仍属于低置信估算，不能证明不存在同时发生的其他设备消费。
